# Mini-UNA — план развития

## Куда идём

Юна — локальный голосовой пилот телефона: слышит по имени, понимает разговорные команды (включая нечёткие), ведёт многошаговые дела (спрашивает недостающее), работает с музыкой/видео/плейлистами, знает экран и уведомления, болтает по-человечески. Всё — на устройстве, без облака.

## Фаза 1. Понимание и диалог ⬅ сейчас здесь

- [x] Будильник: `SET_ALARM` (часы, минуты, дни) через `AlarmClock`
- [x] Громкость в процентах: `VOLUME_PERCENT`
- [x] Слоты и опрос: недостающее спрашивается голосом («Во сколько?», «На какие дни?»), ответ добивает команду; «отмена» сбрасывает
- [x] Персона: приветствия по времени суток, «кто ты», «как дела», «спасибо», «пока» (canned, без инференса)
- [x] Музыка играет по-настоящему: открыть + PLAY + фоновая проверка `isMusicActive()` с доп. нажатием
- [ ] Болталка через Needle (conversational fallback, `SAY`) — после валидации serve на устройстве

## Фаза 2. Фон и хотворд «Юна» ⬅ сейчас здесь

- [x] `HotwordService` (foreground, тип `microphone`): непрерывный `SpeechRecognizer`, гейт по «юна/уна», команда после имени выполняется; иконка в шторке
- [x] Включение/выключение голосом («слушай юну» / «хватит слушать»)
- Честные ограничения (в README): ест батарею; Doze и Xiaomi могут прибивать (инструкция «без ограничений»); с выключенным экраном — best effort; хотворд без DSP = постоянное распознавание; системного уровня не будет без системных привилегий
- Манифест: `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MICROPHONE`, `singleTop` для доставки команд

## Фаза 3. Глубокие интеграции

- [x] Мост Mini-UNA ↔ NeonWave: explicit intent `AUTOPLAY` (+`playlist`) → автовоспроизведение (недавнее/первое/плейлист) → автовозврат `SystemNavigator.pop()`. Без входа в UI плеера не обойтись (нужен живой движок), но задержка ~1с. Требует пересборки NeonWave (код уже внесён: `neonwave/bridge` channel + `bridge_service.dart`)
- Внутри приложений: поиск/плейлисты YouTube, черновики Telegram; следующие шаги — по запросам
- Экранные действия: «нажми на …» по тексту ноды ✅ (сделано: `SCREEN_TAP`); чтение областей экрана — дальше
- Уведомления: быстрые ответы на избранное (RemoteInput) ✅ (сделано: `NOTIF_REPLY` + новые контакты), тихие часы — дальше

## Фаза 3.5. Юна-напарник (Джарвис-лайт, наследник Una-desktop)

- [x] Заметки: много штук с историей, список, очистка (с подтверждением)
- [x] Списки: «добавь молоко в покупки», «что в списке», «убери X» (канонические имена списков)
- [x] Календарь устройства (`READ_CALENDAR`): «что у меня сегодня», «что завтра», «что дальше» (следующие 7 дней)
- [ ] Проактив: утренняя сводка (расписание + дни рождения?) по `AlarmManager` — следующим заходом
- [ ] Синхронизация с Una-desktop: общий протокол заметок/списков (когда будет desktop-API)
- Родство: Una-desktop — старшая сестра (десктоп), Mini-UNA — младшая (телефон). Философия одна: локально, без облака, напарник а не пульт

## Фаза 4. Качество и вес

- Стрип `libcactus_engine.so` в CI (`llvm-strip --strip-debug`): APK 99 → ~45 МБ
- Инференс полностью в фон + переиспользуемый буфер (фон уже есть; инференс — когда оживёт Needle)
- Gradle wrapper + `lint`/`ktlint` в CI + JVM-тесты маршрутизации (стенд описан в `ANALYSIS_REPORT.md`, приложение B)
- Объединение двух каталогов приложений; сужение accessibility-конфига; `versionName` растёт; строки в ресурсы; `ActivityResultLauncher`

## Фаза 5. Needle полный цикл

- Валидация serve на устройстве (статус «локальный сервер активен»)
- Качество роутинга с системным промптом (`--forced`, `--depth`, порог confidence)
- Апстрим `cactus#813`: готовый бандл needle3 → возврат к JNI или официальный путь
- Офлайн-ASR (Cactus `nativeTranscribe`) вместо `RecognizerIntent`; `RECORD_AUDIO` станет осмысленным

## Фаза 6. Параллельные и фоновые задачи

- [x] Параллельное исполнение: независимые действия идут разом (пул 3), системная навигация — строго по порядку
- [x] Фоновые напоминания `REMIND` → `AlarmManager` + уведомление + озвучка
- [x] Ответы на уведомления (`NOTIF_REPLY` через кнопку ответа), оповещение о новых контактах
- [x] Тапы по экрану (`SCREEN_TAP` — руки для текстового «зрения»)
- [x] Точные будильники (`setExactAndAllowWhileIdle` + `SCHEDULE_EXACT_ALARM`; без права — неточно + подсказка «разреши точные будильники»)
- [x] Периодические вотчеры: утренняя сводка (`BRIEFING_SET/OFF`, `setInexactRepeating` daily, ребут через `BOOT_COMPLETED`)
- [ ] Ещё вотчеры (вечерний итог, почасовой «ты тут?» — по запросу)

## Фаза 7. Живой маскот

- Состояния: думает (блуждающий взгляд ×5 быстрее + глаза шире) / спит через 45с покоя (`zzz`, без моргания) / просыпается от касания и команд
- Свободная жизнь: раз в 3.5с случайный взгляд, дыхание, дрейф; плавные переходы эмоций
- Отзывчивость кнопок: ripple на всех стилях (`selectableItemBackground`), SVG-иконки вместо эмодзи (микрофон)
- Плавность: vsync-цикл (`postInvalidateOnAnimation`, без дрейфа 33мс), dt-нормализация сглаживаний — одинаково на 60/120 Гц
- Взгляд: полный вертикальный ход, дальность до 0.40, дефолт 60
- Эмоции по действиям: думает → блуждает; успех → моргание; дальше — по скриншотам «кривых» эмоций
- Глюк «резко пропадает» лечится этим же заходом (рестарт цикла по видимости + vsync); если останется — нужно видео

## Приёмка

- Фаза 1: «поставь будильник» → два вопроса → будильник стоит; «громкость на 50%» работает; «привет» утром/днём/вечером — к месту; «включи музыку» — звук идёт, а не только открывается плеер
- Фаза 2: «Юна, включи музыку» при свёрнутом приложении выполняется; иконка сервиса висит; «хватит слушать» останавливает
- Фаза 4: APK ≤ 50 МБ; `./gradlew lint test` зелёные в CI
- Фаза 5: 8/10 нечётких команд роутит верно
